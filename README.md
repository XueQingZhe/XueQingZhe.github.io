# 吟处雪轻遮 · 水亭

Astro 静态个人网站：水亭入口、日夜光影、作品画廊、技术文章、系统研习与全文搜索。首页使用 Three.js，内页使用轻量环境动效，文章支持专注阅读与本地阅读进度。

## 本地启动

需要 Node.js 22 或更新的受支持版本。首次使用运行 `npm ci`，之后双击 `启动网站.cmd` 或运行 `npm start`。

本机的正式源目录是 `F:\MyWeb\github-pages-release`。日常更新文章可直接双击 `F:\MyWeb\文章发布管理器.cmd`，它会启动预览和管理器并打开浏览器；请保留启动窗口。`F:\MyWeb\启动网站.cmd` 及旧 `astro-site` 的启动入口也会转向正式源目录。

- 网站预览：<http://127.0.0.1:4325/>
- 文章发布管理器：<http://127.0.0.1:4875/>
- 修改网站样式时，可单独运行 `npm run dev` 使用 Astro 热更新；预览生产版本先运行 `npm run build`。

启动器会验证端口上确实是这个网站的服务。默认端口被旧版本占用时，会自动选择下一个空闲端口，并打开正确的页面；实际地址以启动窗口为准。显式指定的端口不会自动改变。默认仅监听本机回环地址。打开管理器不会自动上传文章。

## 文章发布

网站只有三种内容入口：**作品**展示独立作品与作品合集；**手记**索引全部公开内容，每个网址只出现一次；**研习**按系列和篇序组织学习文章。文章类型、研习系列、作品合集关系和 Tag 分别管理，修改类型保留原网址。

打开管理器后，首先显示网站现有内容。工具核对网站文件、发布设置、笔记来源和 GitHub main：**已上传**表示源文件及相关设置与远端一致，**待上传修改**表示本地有改动，**仅本地**表示尚未上传，无法连接远端则显示**未核实**。此处的上传状态不等于 Pages 已部署，部署结果以下方发布进度为准。已保存但未写入网站的设置会另外标记。

已有文章直接点击“发布设置”，读取当前标题、日期、类型和 Tag；即使找不到对应的笔记文件，也能修改网站设置。选择研习类型才显示系列和篇序，研习文章必须选择或创建系列；选择作品才显示单篇 / 合集、封面、引擎等设置。Tag、内容分类与系列可以从已有选项点选，也能新建。内容分类是可选的列表筛选条件，不创建新页面；系列用于按篇序组织研习文章，作品合集使用独立的成员目录。点击“保存发布设置”即完成保存。

作品合集通过“新建作品合集”创建，在同一个编辑界面设置独立封面、名称、简介、Tag 和有序目录，一次保存。封面默认从当前成员文章里的图片、视频静态封面中选择，也可明确复制首篇成员封面或切换到全站图片库；之后调整成员不会改变合集封面。成员支持拖动和上移 / 下移。合集是独立入口，不再通过把一篇文章改成合集来创建。合集可包含普通文章、研习文章和单篇作品，不能包含其他合集。移除成员保留文章；移除最后一篇后仍保留空合集。已有 UE5.5 专题及其三篇文章会被读取，无须重新导入。合集页先展示封面、简介和编号目录；旧的合集长篇介绍折叠在目录后，成员完整正文留在原网址。作品画廊展示合集与未归入合集的独立作品，手记仍索引全部内容。研习顶部只展示“我独自升级、Unity、UE、Blender”四个方向，下面按方向展示全部细分系列。新增系列、追加文章与调整篇序会自动更新下方目录和顶部统计。

“从笔记库添加”展开真实多层目录，支持文件夹勾选、当前层 / 子目录、标题 / 路径 / Tag 搜索和类型筛选。只有正文和媒体明确且唯一一致的笔记才自动关联原网址；相似标题、多版本和不明确的内容保留待确认。自动核对不会自动选中文章。勾选表示纳入正文同步；取消已生成笔记会在审核时列出撤回或恢复网站原文。已关联文章从两处进入设置时使用同一套网站设置。

新导入作品的封面可从笔记图片 / 视频缩略图库选择，支持引用 / 全部素材、搜索、分页和类型筛选。视频生成静态封面，作品卡片悬停 / 聚焦时静音预览，详情页可播放；MOV / M4V 转为 MP4，需要 FFmpeg。网站已有作品也默认显示本篇正文引用的图片与视频，可按类型、文件名筛选；全站素材需要主动切换范围。原笔记及媒体保留在本机。

批量设置作用于当前筛选中已勾选的笔记，支持内容类型、分类、研习系列和追加 / 替换 / 移除 Tag；已有网站条目写入统一设置，新笔记保存导入设置。修改后点击“检查待发布变更”，审核附件，生成待预览副本，再写入本地网站。保存不等于上传，存在待写入设置时不能直接跳到发布。

管理器采用暗色主题。附件可以按类型、文件名、体积区间（MB）与审核状态筛选，并按大小排序。例如筛出 ≥ 1 MB 的图片，批量应用“优化体积”，再点击“确认筛选结果”；小图可批量选择“保留原件”。批量操作仅作用于当前筛选结果，切换筛选会保留其他附件的设置与确认状态。更改压缩方式后自动更新分析，发生变化的附件需要重新确认；隐藏的未确认附件也必须审核后才能生成副本。GIF / 视频可在 FFmpeg 可用时转 MP4，PDF 保留原件。生成副本后会显示实际压缩前后体积。

日常发布分两步：

1. **写入本地网站**：生成副本后点击“确认写入本地网站”，在页面内核对写入与撤回数量，再点击“开始写入本地网站”。按钮旁会显示等待时间、完成结果或失败原因；如果按钮不可用，也会说明尚缺哪个步骤。写入成功后打开网站预览确认内容，此时线上网站尚未改变。
2. **发布到 GitHub Pages**：在管理器中检查待上线的文章和附件，确认后发布。工具完成检查、提交和推送，GitHub 随后自动构建并部署。以管理器显示部署完成为准。

修改或撤回文章也走同样的两步。发布失败时先查看管理器显示的原因和部署详情；修正问题后刷新状态或重试发布。推送完成后，即使关闭本机，GitHub 的后台部署也会继续；重新打开管理器可查询结果。推送前请保留启动窗口。

写入时会构建 Astro 和 Pagefind，再一起切换内容、附件、搜索索引和网站预览；构建或切换失败会回滚。源笔记不会被编辑。撤回文章需要取消选择并完成同样的审核流程。文章移动后保持公开地址；移动同时改写时可手动重新关联。

站点副本分别位于 `content/published/notes/` 和 `public/published-assets/`。私有选择、缓存、暂存及备份在网站外的 `../private-publisher/`，不能放进 Git。跨笔记引用只允许已选文章，附件必须明确审核。动态 Dataview、脚本和不支持的 HTML 会阻止生成并提示处理。

可以通过 `PUBLISHER_VAULT`、`PUBLISHER_STATE` 指定笔记和私有状态路径；`SITE_PORT` 与 `PUBLISHER_PORT` 调整预览和管理端口。启动器固定使用所在网站目录；独立启动管理器时可用 `PUBLISHER_SITE` 指定网站，`PUBLISHER_PREVIEW_URL` 控制预览链接。视频转码需要本地 FFmpeg，未安装时可保留原件。

## GitHub Pages

正式域名：<https://xueqingzhe.github.io/>。构建站点根路径，不添加仓库名作为 base。

`.github/workflows/deploy.yml` 在 PR 上运行检查，更新 `main` 后构建并将 `dist/` 发布到 `gh-pages`。沿用原站的 Pages 分支配置：`Deploy from a branch` → `gh-pages` → `/ (root)`。`.nojekyll` 已包含，避免重复执行 Jekyll。

本地写入不会自动上线；点击管理器中的 **“发布到 GitHub Pages”** 并确认后，才会提交和推送本次文章更新。推送到 `main` 后由 GitHub 自动完成部署，不需要手动输入 Git 命令。发布按钮用于已审核的文章及附件；网站程序更新由开发流程处理。不要执行旧版 Obsidian 同步工具，也不要把整个私有笔记库复制到仓库。

## 验证

```sh
npm test
npm run test:integration
npm run test:workflow
npm run build
npm run check:site
npm run check:release
```

可选浏览器测试：安装 Playwright Chromium 后运行 `npm run test:ui`；已安装 Chrome 或 Edge 时可设置 `PUBLISHER_TEST_BROWSER=chrome` 或 `msedge`。`npm run test:sections` 验证三个入口、新增内容分类和 Tag 从发布生成、构建到网页筛选及搜索的完整流程。视频测试可设置 `PUBLISHER_TEST_FFMPEG` 指向 FFmpeg。所有测试使用独立合成笔记，不读取真实笔记库。`test:workflow` 通过真实 HTTP 服务、Chrome、Astro 构建和隔离的本地 Git 远端，验证核对、修改设置、创建合集、导入、写入、上传状态与重新扫描的完整流程。

`check:site` 检查旧文章链接、站内资源和数学公式；`check:release` 检查公开产物边界、站点大小及 GitHub 单文件限制。

## 目录

- `src/`：页面、组件、样式、场景脚本及已迁移文章。
- `public/`：会直接公开的图片、字体、媒体与站点文件。
- `content/published/notes/`：明确选定的笔记副本。
- `tools/publisher/`：仅在本机运行的发布工具。
- `docs/`：迁移记录、设计说明和检查结果。
- `work/`：本地试验与临时素材，已忽略。
- `dist/`：构建结果，交给部署工作流，不手动加入源分支。
